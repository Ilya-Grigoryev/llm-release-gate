# What it catches

This page lists the kinds of changes the gate notices, the checks that see them and what stays out of sight. The set of
checks is open: you can add your own.

## Two conditions

**1. The change is part of the version**: its config, the bytes of its prompts and the repository's code as git sees it
([What a version is](/docs/how-it-works#what-a-version-is)). Documentation, CI, `gate.yaml` and the test sets do not
count; a request that changes nothing else gets `unchanged`, and nothing runs.

**2. A case looks at it.** Today the gate blocks (`quality fail`) when the candidate's mean score on one run is lower
than the base's by more than `delta` points, 5 by default ([How it decides](/docs/how-it-decides)). A change that no
check looks at cannot lower a score.

## Deliberate changes and engineering changes

A deliberate change of behaviour, such as a new business rule, makes the old cases wrong: update them in the same
request. An engineering change, such as a reworded prompt or another model, should not change behaviour, but noise can
block it or hide a real drop. In the author's measurement on a support agent, one unchanged version's mean moved between
0.4 and 0.7 over 11 runs of the same 10 cases ([How it decides](/docs/how-it-decides#the-same-version-answers-differently)).

## Prompt and policy edits

The made-up booking assistant's policy says: "Credits above €30 go to a manager." This case has a customer cancel late a
booking worth €45:

```yaml
# golden/booking/late-cancel-45.yaml
id: late-cancel-45
version: 1
input: {ticket: late-cancel-45.txt}
expected:
  state_change: {B-104: cancelled}
scoring:
  method: checks
  aggregate: all
  checks:
    - {id: acted, kind: active}
    - {id: verified, kind: order, first: find_customer, then: [cancel_booking, grant_credit]}
    - {id: no-big-credit, kind: not_called, tool: grant_credit, args: {amount_eur: {gt: 30}}}
    - {id: escalated, kind: called, tool: escalate_to_manager}
    - {id: state, kind: state, key: state_change}
```

If a request raises the limit to €75, the candidate issues the €45 credit itself, three checks fail and the case drops
from 1 to 0: on 10 cases where nothing else moves, the mean drops by 10 points and the gate blocks. The assistant's other
rules are seen the same way: "look up the customer before you change a booking" by `order`, "bookings last at most 4
hours" and "do not guess which booking; ask" by `not_called`, "pick the smallest room that fits" by `actions` or
`state`.

## Model and parameters

Another model may follow a rule less reliably, write dates or amounts in another format, take more steps or cost more.
`field_match` with typed fields compares a `date` or a `number` by value, so a new format passes as long as it parses.
For a model name without a date the comment warns, and the gate reports an infra error when runs of such a model
cannot be compared ([How it decides](/docs/how-it-decides#why-both-versions-run-at-the-same-time)).

## Tools

A vaguer description, a changed argument or a new tool makes the agent call the wrong tool, skip one or take a
shortcut; `state` fails on any change to the world the case did not expect. When a request renames an argument such as
`amount_eur`, update the conditions that name it, or `not_called` passes whatever the agent does.

## Code around the call

A new parser reads `1,207.50` as `1.2075`. Your application's own retries add model calls that `max_steps` and the
budgets count. A context cut to the last six messages loses a booking number given early. A new chunk size or `top_k`
returns the wrong article, which `doc_found` sees once you record retrieval as a trace step.

## Dependencies

A new SDK release changes a default, such as a timeout or a retry policy. The lock file belongs to no single pipeline,
so every pipeline runs, each version with its own dependencies; budgets catch a change in cost or speed.

## Knowledge files

An edited FAQ article contradicts the prompt, or a removed document makes retrieval return something else. Files your
application reads from the repository are code, except `docs/` at the root and files named `README`, `CHANGELOG`,
`CONTRIBUTING` or `LICENSE`: take those back in `ignore` with a quoted pattern such as `"!docs/kb/"`
([Reference](/docs/reference#gate-yaml)).

## What it cannot see

- **A change no case touches.** If your cases have credits of €30, €45 and €60, raising the credit limit from €30 to
  €40 changes nothing for any of them.
- **One case on a large set.** With 20 cases, one case going from 1 to 0 lowers the mean by exactly 5 points, which is
  at the limit and passes. Read the comment's list of cases that got worse even on a pass.
- **Changes outside the version**: untracked files, environment variables, data outside the repository, services your
  tools call, a provider's change behind a model name.
- **Changes smaller than the noise** of one run per version.
- **Qualities no built-in check expresses**, such as tone, unless code can express them in a `function` check.

To find gaps, break your application on purpose in a branch (delete one rule, change one number) and open a request:
if the gate does not block, no case checks that rule, or noise hid it.

## Add your own check

A `function` check names a Python function as `module:function`. The gate calls it with `expected`, `output` (or
`None`), `trace` (or `None`) and `spec`, the check's own entry including any keys you add. It returns `True`, `False`, a
share between 0 and 1, `None` when the check does not apply, or a mapping of these for one result per item (`id.key`).

For example, the invoice reader's total must equal the sum of its line items:

```python
# src/invoice_reader/checks.py
from decimal import Decimal, InvalidOperation


def total_adds_up(expected, output, trace, spec):
    """The extracted total equals the sum of the extracted line amounts."""
    if not expected.get("lines"):
        return None  # this invoice has no line items: the check does not apply
    try:
        total = Decimal(str(output["total"]))
        items = sum(Decimal(str(line["amount"])) for line in output["lines"])
    except (KeyError, TypeError, InvalidOperation):
        return False  # no answer, a missing field or a value that is not a number
    return abs(total - items) <= Decimal(str(spec.get("tol", 0)))
```

Name it in a case; the gate passes keys of your own, such as `tol`, in `spec`:

```yaml
# golden/invoices/invoice-017.yaml, other keys left out
expected:
  lines: [{amount: "1000.00"}, {amount: "207.50"}]
scoring:
  method: checks
  checks:
    - {id: adds-up, kind: function, function: "invoice_reader.checks:total_adds_up", tol: 0.01}
```

`uv run llm-release-gate golden validate golden/invoices` imports the function and checks that it can be called. The
module must belong to an installed package ([Get started](/docs/start#option-a-a-python-adapter)); a loose `checks/`
folder at the repository root fails with `ModuleNotFoundError`.
