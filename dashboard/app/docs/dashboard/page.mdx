# Dashboard

The dashboard shows the gate's results by repository: each pipeline's verdict on each pull request, the cases that
changed between the two versions, and what each version answered, called and scored on every case. A **gate run** is
one pipeline gated once on one pull request; other terms are on [Reference](/docs/reference#terms).

## What it shows

**Projects.** Your repositories, each with its last verdict, pull request, date and number of stored gate runs.

**A project.** Its 300 newest gate runs: four numbers, a chart of the base's and the candidate's mean score
per gate run, and a table of the gate runs, newest first; each pipeline's gate run is its own row. When both sides ran the same version, the dashboard marks the gate
run: any gap is run-to-run noise. In the author's measurement on a support agent, one version, left as it was, ran 11
times on the same 10 cases, and its mean score ranged from 0.4 to 0.7.

**A gate run.** The verdict and its rule, both mean scores, the difference and the limit, each side's cost and the
hashes. Below, every case, the changed ones first, with the checks that changed. With `k` above 1, the table averages a
case's runs; the verdict's mean reads only the first, its rule on checks all of them.

**A case.** Its input and expected answer, then both versions side by side, run by run: score, model, tokens,
time, retries and errors, the answer, every check, the steps and the final state.

## How gate runs get there

Your CI sends nothing to the dashboard, and your workflow needs no extra step or secret. When a workflow run finishes,
GitHub notifies the dashboard's App, which downloads the run's gate artifacts (`release-gate-NAME-ATTEMPT` and
`release-gate-NAME-ATTEMPT-cases`) and stores each pipeline's as one gate run.

<Fig id="dashboard-2" caption={"The gate action leaves its results on GitHub; the dashboard's App reads them from there after each run."} alt={"Diagram: the gate action in your workflow uploads artifacts to GitHub. When the run finishes, the dashboard's GitHub App reads those artifacts and stores them; a button reads them again by hand. You see them after signing in with GitHub. If a notification fails, click **Read runs from GitHub** on the project. A stored gate run stays after GitHub deletes
the artifact. Requests from forks and results from CI systems other than GitHub Actions do not reach the dashboard.
For inputs that are not text, such as scanned invoices, `inputs-url` on the pipeline gives the case page a link;
`cases: false` on the gate's step leaves the case files out ([Reference](/docs/reference)).

## Add a repository

On **Projects**, **Add repositories** opens GitHub's page to install the App; pick the repositories that run the gate.
It asks for read-only Actions and Metadata, then reads the gate runs GitHub still keeps. The records and case files
hold your application's answers, tool calls and test inputs, so install the App only on repositories whose results may
leave CI. Today it can be installed only on repositories of the gate's owner.

## Sign in

Open **Projects** in this site's header and click **Sign in with GitHub**; there is no separate account. You see a
repository when the App is installed on it and you have access to it on GitHub.
