# Connect your app

The gate needs one thing from your application: a way to answer one test case. You give it that as a small Python
adapter or as a program in any language that reads a JSON request and writes a JSON answer. Either way, the run can
also report its steps, so checks can look at what an agent did. Terms: [Reference](/docs/reference#terms).

## Two ways in

| | Python adapter | Any program |
|---|---|---|
| You write | a module with `build(config)`; its object answers `run(case)` | a program that reads one JSON request on stdin and writes one JSON answer on stdout |
| The config says | `pipeline: my_app.gate_adapter` | `pipeline: command` and `command: [program, argument, ...]` |
| Runs | inside the gate's runner process | as a new process for every run |

Both give the gate an answer, optionally a trace, tokens and the model the provider reported. Either is code in your
repository, so the gate runs the request's code with your provider key
([Limits](/docs/limits#it-is-not-a-security-control)). The examples are made up: a **booking assistant** (an agent with
tools) behind a Python adapter, and a **support chat** (a dialog with a simulated customer) as a Node program.

## A Python adapter

The gate imports the module named in `pipeline`, calls its `build(config)` once per version, then calls the returned
object's `run(case)` once for every case and repetition.

```yaml
# configs/booking.yaml: the version in production
pipeline: booking_assistant.gate_adapter  # the module with build(config)
model: gpt-4.1-mini-2025-04-14
prompt: ../prompts/policy.md
input: request                            # the case input this version reads as the user's message
params: {temperature: 0}
timeout_s: 120                            # passed to the SDK below; the gate does not stop a Python run
```

```python
# src/booking_assistant/gate_adapter.py
"""The gate's view of the booking assistant: one request to the agent per case."""

import time

import openai
from openai import OpenAI

from llm_release_gate.pipeline import Answer, Fatal, Retryable

from booking_assistant import agent
from booking_assistant.world import World


class Adapter:
    def __init__(self, config):
        self.config = config
        self.policy = config.prompt.read_text()
        # The gate retries and counts retries, so the SDK must not. The gate does not stop a slow Python run,
        # so the SDK's timeout is the limit.
        self.client = OpenAI(max_retries=0, timeout=config.timeout_s)

    def run(self, case):
        world = World.load(case.inputs["world"])  # a fresh copy of the booking system for this run
        request = case.inputs[self.config.input].read_text()
        start = time.perf_counter()
        try:
            result = agent.run(
                self.client, world, self.policy, request, model=self.config.model, **self.config.params
            )
        except openai.RateLimitError as e:
            if getattr(e, "code", None) == "insufficient_quota":
                raise Fatal(str(e)) from e  # out of quota: no call can succeed, stop all runs of this version
            raise Retryable(str(e)) from e  # rate limit: the same call may succeed later
        except (openai.APIConnectionError, openai.InternalServerError) as e:
            raise Retryable(str(e)) from e  # timeout, network, server error
        except (openai.AuthenticationError, openai.NotFoundError) as e:
            raise Fatal(str(e)) from e  # wrong key or model
        return Answer(
            output={"reply": result.reply},
            raw=result.reply,
            input_tokens=result.tokens_in,
            output_tokens=result.tokens_out,
            latency_s=time.perf_counter() - start,  # the whole case: the latency budget reads it
            model=result.model,  # the model the provider reported
        )


def build(config):
    return Adapter(config)
```

`agent` and `World` stand for your application's code. Do not read the case's `expected` or `scoring`: an adapter
that sees the expected answer makes the test meaningless. Return an `Answer` whenever the application produced one,
even a wrong one (`output=None` scores as a miss), and raise only when the run itself broke
([Exit codes and timeouts](#exit-codes-and-timeouts)).

## Any program

```yaml
# configs/support.yaml
pipeline: command
command: [node, chat/gate.js]   # relative to where the runner starts: the project's directory on a pull request
model: gpt-4.1-mini-2025-04-14
prompt: ../prompts/support.md
input: customer
params: {temperature: 0}
timeout_s: 180                  # bounds the whole program; on timeout the gate kills it and retries
```

For each run, the gate starts the program in the runner's working directory, writes one JSON request to its stdin and
reads one JSON answer from its stdout. Write logs to stderr. The request never holds the case's expected values; ignore
fields you do not know:

```json
{"protocol": 1,
 "case": {"id": "refund-double-charge",
          "inputs": {"customer": "/abs/path/golden/support/inputs/refund-double-charge.yaml",
                     "shop": "/abs/path/golden/support/inputs/shop.yaml"}},
 "config": {"model": "gpt-4.1-mini-2025-04-14", "prompt": "/abs/path/prompts/support.md", "input": "customer",
            "params": {"temperature": 0}}}
```

In the answer only `output` is required:

```json
{"protocol": 1, "output": {"reply": "I have refunded the second payment, P-5531. Your refund reference is R-0412."}}
```

[Protocol](/docs/reference#protocol) lists every field. Stdout that is not JSON, or an answer that breaks
`protocol.schema.json`, fails the run.

### A full program

The support chat plays a dialog with a simulated customer, records each model call as a step and maps its errors to
exit codes:

```js
// chat/gate.js: the support chat under the gate, one dialog with a simulated customer per run
const fs = require("fs");
const { APIConnectionError } = require("openai"); // the SDK your application calls
const { runDialog } = require("./src/dialog"); // your application

function exitCode(error) {
  // no call can succeed (out of quota, wrong key, wrong model): stop all runs of this version
  if (error.code === "insufficient_quota" || error.status === 401 || error.status === 404) return 78;
  // may succeed later (network, timeout, rate limit, server error): retry this run
  if (error instanceof APIConnectionError || error.status === 429 || error.status >= 500) return 75;
  return 1; // anything else, a bug in your code included: this run fails
}

let input = "";
process.stdin.on("data", (chunk) => (input += chunk));
process.stdin.on("end", async () => {
  const request = JSON.parse(input);
  const steps = []; // filled as the dialog goes, so paid calls are kept even if it fails
  const record = (actor, response) =>
    steps.push({
      kind: "llm",
      actor, // "agent" for the assistant, "user" for the simulated customer
      status: "ok",
      model: response.model,
      tokens_in: response.usage.prompt_tokens,
      tokens_out: response.usage.completion_tokens,
      cost_usd: null, // the gate prices the step from its price file
      text: response.choices[0].message.content,
    });
  try {
    const read = (name) => fs.readFileSync(request.case.inputs[name], "utf8");
    const prompt = fs.readFileSync(request.config.prompt, "utf8");
    const result = await runDialog(read("customer"), read("shop"), prompt, request.config, record);
    const trace = { steps, final_state: result.shop, state_change: result.changes, stop: result.stop };
    const answer = { protocol: 1, output: { reply: result.reply }, model: result.model, trace };
    process.stdout.write(JSON.stringify(answer));
  } catch (error) {
    process.stdout.write(JSON.stringify({ protocol: 1, output: null, trace: { steps, stop: "error" } }));
    console.error(error.message); // stderr: the end of it goes into the run's error
    process.exitCode = exitCode(error); // not process.exit(): let stdout finish writing
  }
});
```

`runDialog` stands for your application. Create its OpenAI client with `maxRetries: 0`, and map your own SDK's errors
the way `exitCode` does, keeping a bug in your own code at exit 1 so it is not retried.

### What the project still needs today

A project in another language still needs a small `pyproject.toml` and `uv.lock` that list the gate
([Get started](/docs/start)). Install the program's dependencies with `prepare` in `gate.yaml`
([example](#several-pipelines-in-one-gate-yaml)). `prepare` comes from the request but also runs in the target
branch's checkout: if one request adds the Node program and `prepare: [npm, ci]`, `npm ci` fails there and every
pipeline gets `infra error`. Merge the package files first, or use
`prepare: [sh, -c, "test ! -f package-lock.json || npm ci"]`.

## Exit codes and timeouts

| Adapter raises | Program exits | What the gate does |
|---|---|---|
| returns | 0 | reads the answer |
| `Retryable` | 75 | rate limit, timeout: retries after 1, 2, 4… seconds (at most 60), up to `max_retries` times |
| `Fatal` | 78; 126, 127 from a shell in `command` | no quota, wrong key: stops all runs of this version |
| any other exception | any other code | records the error, goes on with the other cases |

A program the gate cannot start also stops all runs. A run with no answer after its retries gives the pipeline
[`infra error`](/docs/read-a-verdict#infra-error) (exit 20), not a lower score, so return a wrong answer as an answer.

`timeout_s` bounds a whole program: on timeout the gate kills its process group (POSIX only) and retries the run like
an exit 75; a child that leaves the group (`setsid`, `docker run`) survives. The gate does not stop a Python `run`:
pass `config.timeout_s` to your SDK and turn off its retries (`max_retries=0`), so the gate counts every retry.

On a pull request up to eight runs go at once, four per version, so size shared resources for that. An adapter's
`build` runs once: keep per-case state in `run`.

## Traces

A trace is the list of steps in one run, with the state of the world at the end. Trace checks such as `called` or
`state` read it; without a trace, they fail. Each step has a kind (`llm`, `tool`, `message`, `retrieval`) and an actor
(`agent`, `user`, `system`, `env`); trace checks look at `agent` steps unless a check names
another `actor`. Fields: [`trace`](/docs/reference#trace).

The gate prices every model step by its `model` name from the price file, whatever `cost_usd` it carries, so send
`cost_usd: null`. An unknown model leaves the run without a cost, and with a cost budget the pipeline gets
`infra error`.

### Record a trace in a Python adapter

The gate keeps one trace per run, current while `run` executes. Three changes to the adapter above record into it:

```python
from llm_release_gate import trace

# in __init__: a model step for every chat.completions.create
self.client = trace.openai_client(OpenAI(max_retries=0, timeout=config.timeout_s))

# in run, after loading the world: a tool step for every world.call(name, args)
world.call = trace.wrap_tool(world.call)

# in run, before returning the answer: the end state, for the state check
if (t := trace.current()) is not None:  # None outside the gate's runner
    t.final_state = world.state()
    t.state_change = world.changes()
    t.stop = result.stop  # why the run ended: "done", "max_steps", ...
```

Only `chat.completions.create` is recorded; streamed calls, the Responses API, `parse` and raw responses are not.
Unwrapped tools are rebuilt from the agent's `tool` messages, with status `unknown`.

- **Other calls.** `trace.current().step(kind, actor, **fields)` adds a step by hand, such as an `llm` step for
  another provider or a `retrieval` step (below). A step that breaks the format raises `ValueError`.
- **A simulated customer.** `trace.openai_client(client, actor="user")` records its calls as `user` steps: never the
  agent's, but in the cost budget.
- **Threads your application starts.** Pass `trace=trace.current()` to `trace.openai_client` and `trace.wrap_tool`;
  the trace belongs to the thread that runs the case.

```python
# documents your application retrieved, for the doc_found check (question, found: your search's query and results)
if (t := trace.current()) is not None:
    t.step("retrieval", "agent", query=question, docs=[{"id": d.id} for d in found])
```

### A trace from a program

A program returns the trace in its answer, in the same format, as the full program above does. The gate numbers the
steps and keeps a trace printed before a failed exit, so paid calls count. A retried run keeps every attempt's steps:
trace checks read the last attempt, the cost counts all.

## Several pipelines in one gate.yaml

List each LLM application, or part of one, under `pipelines`; adapters and programs can sit side by side:

```yaml
# gate.yaml
prepare: [npm, ci]                 # readies both trees before their runs: the support chat needs its Node packages
pipelines:
  invoice:
    config: configs/invoice.yaml   # a Python adapter, one model call
    golden: golden/invoices
  booking:
    config: configs/booking.yaml   # a Python adapter, an agent with tools
    golden: golden/booking
    budgets: {cost_per_run_usd: 0.05}  # replaces the top-level budgets for this pipeline
  support:
    config: configs/support.yaml   # a Node program, a dialog with a simulated customer
    golden: golden/support
delta: 5                           # block when the mean score drops by more than 5 points
prices: prices.yaml
budgets:
  cost_per_run_usd: 0.01
  latency_s: 20
```

Top-level `k`, `delta`, `prices` and `budgets` apply to every pipeline unless it sets its own; a pipeline's `budgets`
replaces the top-level one whole, so `booking` has no latency limit. Code belongs to every pipeline: a change to
`chat/gate.js` runs all three. On GitHub Actions, gate one pipeline per step with `pipeline:` and add
`if: ${{ !cancelled() }}` to all steps but the first ([GitHub Actions](/docs/reference#github-actions)). A new
pipeline gets [`no base version`](/docs/read-a-verdict#no-base-version); removing or renaming one fails as
[`inconclusive`](/docs/read-a-verdict#inconclusive).

## A monorepo

Put `gate.yaml` in the project's directory; its paths are relative to it. Give both actions
`project-dir: services/assistant`, or run from the repository's root:

```sh
uv run --project services/assistant llm-release-gate pr --project services/assistant --base origin/main --out gate-out
```

The directory must be a uv project with a committed, current lock file. A version still covers every file git tracks
in the whole repository ([What a version is](/docs/how-it-works#what-a-version-is)), while `ignore` reaches only the
project's directory. Take back help articles under `docs/` with `ignore: ["!docs/kb/"]`.

## Check it on your machine

Before the first pull request, run the version once on its test set, the way CI runs it, without comparing:

```sh
uv run --env-file .env llm-release-gate run --config configs/booking.yaml --golden golden/booking -k 1 --out runs/try.jsonl
```

The last line reports how many runs answered and their mean score:

```text
1 records written, 1 of 1 done, mean score 1.000; config 52de5e7c6e87, set d43dd8cfc283
```

Each line of `runs/try.jsonl` is one run: answer, trace, tokens per actor and check results. A run with
`"trace": null` recorded no steps: check the wrappers.

## Planned

The adapter will run in its own worker process, speaking the same JSON protocol; the action will install the gate, so
a project without Python needs no `pyproject.toml`; a local proxy will record OpenAI API calls as `llm` steps in any
language.
