# Get started

This page takes you from a GitHub repository to a first pull request that the gate answers with a comment. Most steps
end with a check on your machine, so mistakes show up before CI.

## Before you start

- **Access to the gate.** Its repository is private today: only private repositories of its owner can use it
  ([step 1](#1-get-access-while-the-gate-is-private)).
- **A GitHub repository** with Actions turned on, or see [Other CI](#other-ci).
- **A uv project**: `pyproject.toml` and a committed, up-to-date `uv.lock` at the root, Python 3.12 or newer. An
  application in another language still needs a small `pyproject.toml` that lists the gate.
- **An API key** for your model provider. The examples use OpenAI.

The examples use a made-up **invoice reader**: one model call reads the vendor, the date and the total from an invoice.
[Reference](/docs/reference#terms) defines the terms.

## 1. Get access while the gate is private

The owner of the gate's repository does this once per project. In the gate's repository, under Settings → Actions →
General → Access, choose "Accessible from repositories owned by" the owner's account. Then create a key pair, add its
public half as a deploy key without write access, and store its private half as your project's secret:

```sh
ssh-keygen -t ed25519 -N "" -f llm-release-gate-key
gh repo deploy-key add llm-release-gate-key.pub --repo Ilya-Grigoryev/llm-release-gate --title "your-project"
gh secret set LLM_RELEASE_GATE_KEY < llm-release-gate-key   # run inside your project's repository
```

**Check:**

```sh
GIT_SSH_COMMAND="ssh -F /dev/null -i llm-release-gate-key -o IdentitiesOnly=yes" \
  git ls-remote git@github.com:Ilya-Grigoryev/llm-release-gate.git v0.1.0-dev.16
gh secret list   # run inside your project's repository
```

The first command prints a commit id and `refs/tags/v0.1.0-dev.16`; `Permission denied (publickey)` means the gate's
repository does not know the key. The second lists `LLM_RELEASE_GATE_KEY`. Then delete the key files:

```sh
rm llm-release-gate-key llm-release-gate-key.pub
```

## 2. Add the dependency

`uv add` pins the gate to a release and updates the lock file:

```sh
uv add "llm-release-gate @ git+https://github.com/Ilya-Grigoryev/llm-release-gate" --tag v0.1.0-dev.16
```

```toml
[project]
dependencies = ["llm-release-gate"]

[tool.uv.sources]
llm-release-gate = { git = "https://github.com/Ilya-Grigoryev/llm-release-gate", tag = "v0.1.0-dev.16" }
```

Commit `pyproject.toml` and `uv.lock` together: a stale lock file stops the gate in CI. **Check:**

```sh
uv run llm-release-gate pr --help
```

It prints the help of `pr`. If uv cannot fetch the gate, your git cannot read its repository.

## 3. Write gate.yaml

`gate.yaml` at the project's root names, for each pipeline, a version's config and its test set:

```yaml
pipelines:
  invoice:                        # names the comment and the artifact
    config: configs/invoice.yaml  # the version
    golden: golden/invoices       # its test set
delta: 5                          # block when the mean score drops by more than 5 points
```

A case scores from 0 to 1 and the mean score is read in points out of 100, so with `delta: 5` a drop from 0.82 to 0.76
blocks. Each version runs once per case, so a request can block or pass by chance ([How it
decides](/docs/how-it-decides)). Other fields are optional ([Reference](/docs/reference#gate-yaml)), and the rules come
from the target branch's `gate.yaml`. **Check:**

```sh
uv run llm-release-gate pr --list
```

It prints the pipeline names, here `invoice`, or `infra error` with every problem in the file. It does not open the
config or your code; [step 5](#5-write-a-first-case) does.

## 4. Describe the version and connect your app

Your app answers the gate's test cases as a program. For each run the gate starts it, writes one JSON request to its
stdin and reads one JSON answer from its stdout. The request names the case's input file and the version's model, prompt
and parameters; the answer's `output` is what the case's checks score.

The version's config names the program and says which model, prompt and parameters it runs with. The prompt,
`prompts/extract.md`:

```text
Read the invoice below. Answer in JSON with the keys vendor, date and total, copied as they appear on the invoice.
Use null for a value the invoice does not show.
```

The config and the program, in your language:

<LanguageTabs>
<Tab label="Python">

```yaml
# configs/invoice.yaml: the version in production
command: [python, gate/extract.py]  # run from the project's root
model: gpt-4.1-mini-2025-04-14      # a dated snapshot
prompt: ../prompts/extract.md       # relative to this file
input: text                         # which input of a case this version reads
params: {temperature: 0}
```

```python
# gate/extract.py: one request in, one model call, one answer out
import json
import sys
from pathlib import Path

import openai

request = json.load(sys.stdin)
config = request["config"]
invoice = Path(request["case"]["inputs"][config["input"]]).read_text()
prompt = Path(config["prompt"]).read_text()


def fail(code, error):
    print(error, file=sys.stderr)  # the gate keeps it with the run
    sys.exit(code)


client = openai.OpenAI(max_retries=0)  # the gate retries, not the SDK
try:
    r = client.chat.completions.create(
        model=config["model"],
        messages=[
            {"role": "system", "content": prompt},
            {"role": "user", "content": invoice},
        ],
        response_format={"type": "json_object"},
        **config["params"],
    )
except openai.RateLimitError as e:
    fail(78 if e.type == "insufficient_quota" else 75, e)  # no quota or credits: stop; rate limit: retry
except (openai.APIConnectionError, openai.InternalServerError) as e:
    fail(75, e)  # timeout, network, server error: retry this run
except (openai.AuthenticationError, openai.PermissionDeniedError, openai.NotFoundError) as e:
    fail(78, e)  # wrong key or model: stop all runs of the version

raw = r.choices[0].message.content or ""
try:
    output = json.loads(raw)
except json.JSONDecodeError:
    output = None  # no answer: every field scores as wrong
json.dump(
    {
        "protocol": 1,
        "output": output,
        "raw": raw,
        "input_tokens": r.usage.prompt_tokens,
        "output_tokens": r.usage.completion_tokens,
        "model": r.model,  # the model the provider reports
        "fingerprint": r.system_fingerprint,
        "finish_reason": r.choices[0].finish_reason,
        "request_id": r.id,
    },
    sys.stdout,
)
```

The gate runs inside `uv run`, so `python` is your project's interpreter: add `openai` to its dependencies.

```js
// gate/extract.mjs: one request in, one model call, one answer out
import { readFileSync } from "node:fs";

const request = JSON.parse(readFileSync(0, "utf8")); // stdin
const { config } = request;
const invoice = readFileSync(request.case.inputs[config.input], "utf8");
const prompt = readFileSync(config.prompt, "utf8");

function fail(code, error) {
  console.error(error); // the gate keeps it with the run
  process.exit(code);
}

const base = process.env.OPENAI_BASE_URL ?? "https://api.openai.com/v1";
const res = await fetch(`${base}/chat/completions`, {
  method: "POST",
  headers: { "Content-Type": "application/json", Authorization: `Bearer ${process.env.OPENAI_API_KEY}` },
  body: JSON.stringify({
    model: config.model,
    messages: [
      { role: "system", content: prompt },
      { role: "user", content: invoice },
    ],
    response_format: { type: "json_object" },
    ...config.params,
  }),
}).catch((e) => fail(75, e)); // network: retry this run
const r = await res.json().catch(() => ({}));
if (!res.ok) {
  const stop = r.error?.type === "insufficient_quota" || [401, 403, 404].includes(res.status);
  // no quota, wrong key or model: stop all runs; rate limit, server error: retry this run
  fail(stop ? 78 : res.status === 429 || res.status >= 500 ? 75 : 1, `${res.status} ${r.error?.message}`);
}

const raw = r.choices[0].message.content ?? "";
let output = null; // no answer: every field scores as wrong
try {
  output = JSON.parse(raw);
} catch {}
process.stdout.write(
  JSON.stringify({
    protocol: 1,
    output,
    raw,
    input_tokens: r.usage.prompt_tokens,
    output_tokens: r.usage.completion_tokens,
    model: r.model, // the model the provider reports
    fingerprint: r.system_fingerprint ?? null,
    finish_reason: r.choices[0].finish_reason,
    request_id: r.id,
  }),
);
```

It needs Node 18 or newer and no packages.

```go
// gate/extract.go: one request in, one model call, one answer out
package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"net/http"
	"os"
)

type Request struct {
	Case struct {
		Inputs map[string]string `json:"inputs"`
	} `json:"case"`
	Config struct {
		Model  string         `json:"model"`
		Prompt string         `json:"prompt"`
		Input  string         `json:"input"`
		Params map[string]any `json:"params"`
	} `json:"config"`
}

type Completion struct {
	ID                string  `json:"id"`
	Model             string  `json:"model"`
	SystemFingerprint *string `json:"system_fingerprint"`
	Choices           []struct {
		Message      struct{ Content string } `json:"message"`
		FinishReason string                   `json:"finish_reason"`
	} `json:"choices"`
	Usage struct {
		PromptTokens     int `json:"prompt_tokens"`
		CompletionTokens int `json:"completion_tokens"`
	} `json:"usage"`
	Error *struct {
		Type    string `json:"type"`
		Message string `json:"message"`
	} `json:"error"`
}

func fail(code int, err any) {
	fmt.Fprintln(os.Stderr, err) // the gate keeps it with the run
	os.Exit(code)
}

func main() {
	var req Request
	if err := json.NewDecoder(os.Stdin).Decode(&req); err != nil {
		fail(1, err)
	}
	invoice, err := os.ReadFile(req.Case.Inputs[req.Config.Input])
	if err != nil {
		fail(1, err)
	}
	prompt, err := os.ReadFile(req.Config.Prompt)
	if err != nil {
		fail(1, err)
	}

	body := map[string]any{
		"model": req.Config.Model,
		"messages": []map[string]string{
			{"role": "system", "content": string(prompt)},
			{"role": "user", "content": string(invoice)},
		},
		"response_format": map[string]string{"type": "json_object"},
	}
	for k, v := range req.Config.Params {
		body[k] = v
	}
	payload, _ := json.Marshal(body)
	base := os.Getenv("OPENAI_BASE_URL")
	if base == "" {
		base = "https://api.openai.com/v1"
	}
	call, _ := http.NewRequest("POST", base+"/chat/completions", bytes.NewReader(payload))
	call.Header.Set("Content-Type", "application/json")
	call.Header.Set("Authorization", "Bearer "+os.Getenv("OPENAI_API_KEY"))
	res, err := http.DefaultClient.Do(call)
	if err != nil {
		fail(75, err) // network: retry this run
	}
	defer res.Body.Close()
	var r Completion
	json.NewDecoder(res.Body).Decode(&r)
	if res.StatusCode != http.StatusOK {
		said := res.Status
		if r.Error != nil {
			said += ": " + r.Error.Message
		}
		switch {
		case r.Error != nil && r.Error.Type == "insufficient_quota", res.StatusCode == 401, res.StatusCode == 403, res.StatusCode == 404:
			fail(78, said) // no quota, wrong key or model: stop all runs of the version
		case res.StatusCode == 429, res.StatusCode >= 500:
			fail(75, said) // rate limit, server error: retry this run
		default:
			fail(1, said)
		}
	}

	raw := r.Choices[0].Message.Content
	var output map[string]any // nil: no answer, every field scores as wrong
	json.Unmarshal([]byte(raw), &output)
	json.NewEncoder(os.Stdout).Encode(map[string]any{
		"protocol":      1,
		"output":        output,
		"raw":           raw,
		"input_tokens":  r.Usage.PromptTokens,
		"output_tokens": r.Usage.CompletionTokens,
		"model":         r.Model, // the model the provider reports
		"fingerprint":   r.SystemFingerprint,
		"finish_reason": r.Choices[0].FinishReason,
		"request_id":    r.ID,
	})
}
```

Add `bin/` to `.gitignore`, and build once with the same `go build` before the check in [step
5](#5-write-a-first-case): only `pr` runs `prepare`. Do not use `go run` in `command`: it turns every exit code of the
program into 1, so the gate cannot tell a rate limit from a wrong key.

</Tab>
</LanguageTabs>

Only `output` is required in the answer; the tokens and the model let the gate count the cost, and the run's record
keeps `fingerprint`, the provider's mark of the system that answered. The exit code says what went wrong: 75 retries
the run with backoff, 78 (or 126 and 127 from a shell) stops all runs of the version, any other code fails this run. If your application already has this code,
call it from the program with the request's model, prompt and `params`. [Connect your app](/docs/connect) covers agents
and their traces, [Reference](/docs/reference#protocol) every field.

Prefer a model name with a date: for a name without one, the gate warns and in some cases refuses to compare. The
version is this config, the bytes of its prompts and the repository's code as git sees it ([What a version
is](/docs/how-it-works#what-a-version-is)).

## 5. Write a first case

A case is a YAML file in the test set's directory: what goes in, what should come out, and how to score the answer:

```yaml
# golden/invoices/inv-001.yaml
id: inv-001
version: 1                   # the case's own revision, not your app's: raise it when you change what the case asks
input:
  text: inputs/inv-001.txt   # relative to this file
expected:
  vendor: Northwind Supplies Ltd
  date: "14.03.2026"         # quote dates
  total: "1249.50"
scoring:
  method: field_match
  normalise: [whitespace, casefold]
  fields:
    date: {type: date}       # compared by value: 2026-03-14 matches too
    total: {type: number}    # $1,249.50 matches too
```

Its input, `golden/invoices/inputs/inv-001.txt`:

```text
NORTHWIND SUPPLIES LTD
12 Harbour Road, Leeds LS1 4AB

INVOICE 2026-0412                 Date: 14.03.2026
Bill to: Oakline Studio

Printer paper A4, 20 boxes           420.00
Toner cartridges, 6                  604.00
Delivery                              17.25
Subtotal                           1,041.25
VAT 20 %                             208.25
TOTAL DUE                          1,249.50
```

The case scores the share of right fields: two of three give 0.67. Agents use `method: checks` ([Write
tests](/docs/write-tests)). **Check the case:**

```sh
uv run llm-release-gate golden validate golden/invoices
```

It prints the set's hash, or names the file with a problem, such as an ISO date without quotes.

**Check the version: run it once.** This costs one model call per case. Keep `.env` and `runs/` out of git: a run record
you commit becomes part of the version.

```sh
echo "OPENAI_API_KEY=sk-..." >> .env
printf '.env\nruns/\n' >> .gitignore
uv run --env-file .env llm-release-gate run --config configs/invoice.yaml --golden golden/invoices --out runs/first.jsonl
```

It prints the mean score and the hashes. If the program cannot start, the prompt is missing or the key is wrong, it
stops and says which.

## 6. Add the gate to your workflow

Add a job that runs on pull requests, and store your provider's key as the secret `OPENAI_API_KEY`:

```yaml
# .github/workflows/release-gate.yml
name: release-gate
on: pull_request
jobs:
  release-gate:
    runs-on: ubuntu-latest
    permissions: {contents: read, pull-requests: write, actions: read}
    env:
      OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
    steps:
      - uses: actions/checkout@v7
      - uses: Ilya-Grigoryev/llm-release-gate/setup@v0.1.0-dev.16
        with:
          gate-ssh-key: ${{ secrets.LLM_RELEASE_GATE_KEY }}  # while the gate's repository is private
      - uses: Ilya-Grigoryev/llm-release-gate@v0.1.0-dev.16
```

`setup` installs Python, uv and your project's locked environment; the gate step needs `pull-requests: write` to post
its comment and `actions: read` to reuse the target branch's runs from earlier jobs. Use the same tag as in `pyproject.toml`. Optionally, let a new push replace the run for the old one:

```yaml
    concurrency:
      group: release-gate-${{ github.event.pull_request.number }}
      cancel-in-progress: true
```

**Check: run the gate locally.** Commit your files first, so it sees what CI sees:

```sh
git fetch origin main
uv run --env-file .env llm-release-gate pr --base origin/main --out ../release-gate-out
```

It writes `comment.md`, `verdict.json` and the runs to `../release-gate-out/invoice/` and exits with the verdict's code
([outcomes](#what-each-outcome-means)): 0 on your first setup. If it is 20, read `comment.md` and [step
7](#7-open-a-pull-request).

## 7. Open a pull request

Push your branch and open a pull request. The job posts one comment and edits it on later pushes.

**The first time**, the target branch has no version to compare with: the candidate runs alone and the job passes.

<Fig id="start-2" caption={"The first comment. Nothing to compare with yet, so the job passes and the comment reports the candidate's score."} alt={"A comment on the pull request titled \"Release gate: no base version\". It says the target branch has no version of this pipeline yet, so there is nothing to compare with, and that the candidate scores 1.000 on 1 case, with the short hashes of the config and the test set."} />

If the target branch is not a uv project yet, the comment reads "The target branch's project could not be prepared."
(`infra error`): merge `pyproject.toml` and `uv.lock` in a pull request of their own first.

After you merge, later requests are compared with the target branch's version. One that changes only documentation or
other files that do not count gets `unchanged` and calls no model
([When nothing runs](/docs/how-it-works#when-nothing-runs) has the exceptions). A request from a fork gets no secrets and fails as
`not checked`. The job only advises until you make `release-gate` a required status check.

## What each outcome means

`pass`, `unchanged` and `no base version` exit with 0 and leave the job green. `quality fail` (10), `inconclusive` (11),
`budget fail` (12), `infra error` (20) and `not checked` turn it red. [Read a verdict](/docs/read-a-verdict) explains
each outcome and what to do next.

## Other CI

Outside GitHub Actions, install the project with uv and run from the repository's root:

```sh
uv run llm-release-gate comment --running --name invoice   # optional: the note the verdict replaces
uv run llm-release-gate pr --base origin/main --out OUT
uv run llm-release-gate comment OUT/invoice/comment.md --name invoice
```

On GitLab, `comment` needs `GITLAB_TOKEN`, a project access token with the `api` scope
([Reference](/docs/reference#commands)).
